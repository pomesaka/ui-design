# メンバー

小規模チーム向け業務SaaSの「チームメンバー管理」画面。データは[合成](data.ts)。

## 利用者

| 人 | 状況・期待 | 来た目的 | 見た後 |
| --- | --- | --- | --- |
| 管理者(優先) | 入社・退職・外部協力者の出入りのたび。誰がいて誰を招待中か一目で分かってほしい | 招待する、権限を変える、離れた人を削除する、届かない招待を再送・取り消す | 招待した人の参加を待つ。削除・変更が反映されたことを確かめて閉じる |
| 閲覧者・編集者 | 権限が足りない、誰に頼めばよいか分からない | 管理者が誰かを知る、メンバーを探す | 管理者に依頼する |

主操作は管理者の「メンバーを招待」。権限変更とチームから外す操作は各行、整理の入口は「利用のないメンバー」の案内に置く。

チームから外す操作は[破壊操作の置き方](../../docs/composition.md#破壊操作の置き方)のうち、行の`destructive-subtle`と確認Dialogの`destructive`を選んだ。退職者が残る問題が依頼者から挙がっており、外す操作は管理者の目的そのものなので、Menuの奥に入れず見つけやすくした。メンバーは消えず作成した内容が残るため、文言は「削除」ではなく「外す」にした。

一覧の並びは並び順・絞り込み・検索を変えたときと人の増減で決め、権限を変えても行を動かさない。変えた結果がその場に残り、見失わないため。

## 事実と仮定

事実(依頼者から): メンバーは数人〜80人。権限は閲覧者・編集者・管理者。管理者は招待・権限変更・チームから外すことができ、他の人は一覧を見るだけ。招待中の人がいて、再送・取り消しができる。「誰が管理者か分からない」「退職者が残ったまま」という声がある。

仮定(確かめる方法):

- 最終利用日時を記録している。90日以上の利用なしを退職の手掛かりにする(記録の有無と、妥当な日数を依頼者に確認する)。
- 招待の有効期限は7日。管理者以外は招待中の一覧を見ない。
- 最後の管理者は降格・チームから外すことができない。自分を管理者から外すときは確認する。自分を外すこと(チームを抜ける)はこの画面で扱わない。
- 外しても作成した内容はチームに残る。編集者・閲覧者の権限の意味(`roleDescription`)。
- 招待の既定の権限は編集者。権限の変更は確認なしで即時反映する(元に戻せるため)。

## 見方

`/examples/members/`にURL引数を付けて状態を開く。

| 引数 | 状態 |
| --- | --- |
| `as=viewer`・`as=editor` | 管理者以外の視点(変更操作なし) |
| `count=1`・`count=80` | 自分だけ・大量の件数 |
| `invites=0` | 招待なし |
| `state=loading`・`state=error`・`state=refresh-error` | 初回読み込み・取得失敗・更新失敗 |
| `fail=1` | 変更・招待・外す操作が失敗する |
| `theme=luma-dark` | 暗いテーマ |
