# 画面の組み立て方

人間中心設計とユーザビリティの定番の原則(ヒューリスティック)に従う。視覚的なまとまりはゲシュタルトの原則で考え、値は[token](../themes/README.md)、部品の選択は[部品の一覧](../components/README.md)に従う。以下は、それらに加えてこのrepositoryで重視することと決めたこと。既定から外れるときは、利用者・内容・操作の違いで理由を説明する。

## 利用者から始める

配置や見た目より先に、誰が・どんな状況で・何を期待し・何をしに来て・見た後にどう動くかを利用者ごとに書き出し、優先する人を決める。書き出したことは根拠のある事実と推測による仮定を分け、仮定に頼る判断は確かめる方法か直しやすい形を選ぶ。

画面と各案は次の三つで評価する。

1. **叶えられるか。** 各利用者の期待と目的に、この画面で届くか。
2. **阻害していないか。** 優先する人の目的を、他の情報・操作・装飾が邪魔していないか。
3. **迷わないか。** 次に何をすればよいか、操作した結果がどうなったかが分かるか。

## 進め方

1. 利用者のストーリーを書き、優先する人の主な目的から主操作を一つ決める。決まらなければ画面を分ける。
2. 利用者が扱う対象(名詞)を先に挙げ、それを画面の骨格にして、操作は対象に付ける。情報と操作を実際に近いデータで書き出し、重要度と頻度で配置の強さを決める。最長の文字列・0件・大量の件数も用意する。
3. 画面で伝えたいことを一つずつ挙げ、それぞれをレイアウト → デザイン → 言葉の順で解く。言葉にしたものは、レイアウトとデザインで試したことと、伝わらなかった理由を残す。
4. 方向の違う構造の案を2〜3出し、三つの問いで比べて選んだ理由を残す。最初の案はありがちな形になりやすい。
5. 部品とtokenで組み、起こる状態(初回読み込み・空・失敗・更新失敗・権限なし・処理中)を作る。
6. [確認](#確認)し、利用者の目的に要らない要素を削る。

## このrepositoryの決定

- 強弱は位置 → 余白 → 文字 → 色の順で付ける。意味の伝え方も同じく配置から先に、[レイアウト → デザイン → 言葉](../DESIGN.md#内容と操作)の順にする。主操作(`primary`)はページ・Dialog等の一つの操作領域に一つ。
- 文字の段は、ページ見出し`font-heading text-heading`、区画見出し`font-heading text-section`、本文`font-body text-body`、補足`font-control text-caption text-reading-secondary`に限る。labelと操作の文字は部品に任せる。
- 文字の段は、size・line-heightと一緒に太さも決める。`text-body`・`text-detail`・`text-reading`は太さを`--weight-body`にするので、見出しの要素や`<strong>`に付けると、baseの太さを消して細くなる。見出しは`text-heading`・`text-section`にし、本文の大きさの見出し(cardの題等)が要るときは`[font-weight:var(--weight-heading)]`を足す。強調は、段を付けた要素の中に`<strong>`を置く。
- 余白はtokenの段(`1`・`2`・`3`・`4`・`6`・`8`・`12`、`panel`・`reading`)から選ぶ。段外の値と任意値は検査で落ちる。既定は次のとおり。

| 関係 | 既定 |
| --- | --- |
| 同じグループの項目、見出しと補足 | `gap-1`〜`gap-3` |
| 区画見出しと中身、グループ間 | `gap-4`〜`gap-6` |
| ページ直下の区画間 | `gap-12` |
| 一覧の行 | 区切り線と`py-3`。行の操作は`size="sm"` |
| 本文の幅 | 業務画面は`max-w-5xl`〜`max-w-6xl`、文章が主なら`max-w-prose` |

- 区切りは余白 → 区切り線 → 面の順に検討する。一覧の行は区切り線で分ける。カード(面)は一つの対象を選ぶ・比べるときに使い、入れ子にしない。Banner・Notice等の部品が持つ面はこの判断に含めない。影はpopupとDialog、[中身の上に浮く帯](#中身が主の画面)だけが持つ。
- `primary`と状態色(`success`・`warning`・`destructive`・`info`)は意味があるときだけ使い、面積の大半は`background`・`card`・`foreground`にする。
- 結果は時間で消える表示で伝えない。[結果の伝え方](../components/README.md#結果の伝え方)に従う。
- 背景も枠もないボタン(`ghost`)は、iconボタン・Dialogの閉じる・ツールバー等、形や場所でボタンと分かるときだけ使う。一覧や本文に置く控えめな操作は`secondary`にする。
- 破壊操作は[破壊操作の置き方](#破壊操作の置き方)から選ぶ。`destructive`の塗りを繰り返し並べない。
- 項目ごとの識別と少数の値・操作なら`List`、値を列で比べるなら`Table`で組む。行の操作は二つまで見せて残りは`Menu`へ入れ、行を消した後は次の行の同じ操作へfocusを移す。行の値を変えても並びは保ち、並べ替えは利用者が並び順・絞り込みを変えたときに行う。
- ボタンは結果を表す動詞で書き、日本語UIに英字の飾りlabelを混ぜない。
- 値を「項目名:値」の形で並べない。全部が同じ強さになり、強弱を付けられない。値の形(金額、日付、メールアドレス)や置いた場所で何の値か分かるなら、項目名を外す。外せないときは項目名を値の中に入れ(「在庫:12」でなく「残り12個」)、それでも残す項目名は値より控えめにする。表の列見出しと入力欄のlabelはこの対象でない。
- 完了や成功で終わる画面には、次の行き先(一覧、ダッシュボード、元の導線)を出す。完了の画面は文だけで終わりやすく、見た目は正しく完了しているので見落とされる。行き先が無いなら、閉じてよいことを書いて終える。権限等の都合で行き先を出せないなら、理由をコードのコメントに残す。

## 中身が主の画面

ボード・エディタ・地図のように、利用者が作る・読む中身が画面の大半を占め、操作の部品がその上に浮く画面の決定。一覧・表・Dialogを前提にした上の決定は、次のように読み替える。

- 操作の部品は画面の端の帯へまとめ、中身を隠す面積を小さくする。帯は中身の上に浮くので、popupと同じく影を持ってよい。
- 帯の面と文字は`header`の役割で組む。選んでいる道具と効いている切り替えは、`header-accent`の対と`aria-pressed`で示す。
- 中身の色(付箋の色のように、書く人が意味を持たせて選ぶ色)は共通契約の役割へ当てはめず、[サービスの役割](../tokens/README.md#サービスで役割を足す)として足す。操作の部品の色と混ぜない。
- 押せる大きさは`control-hit-size`を保つ。中身を隠さないために小さくするなら、理由を対象の記録に残す。
- [確認](#確認)では、狭い幅で帯が中身や互いを覆わないかを見る。

## 破壊操作の置き方

`destructive`の塗りは画面で最も強い表示になり、繰り返すと主操作より目立って警告に慣れさせる。場面に合わせて次から選び、選んだ理由を残す。

| 選択肢 | 向く場面 |
| --- | --- |
| 確認Dialogの確定ボタンを`destructive` | 取り返しのつかない操作の確定。ボタンは操作名で書く(「チームから外す」) |
| 行に`destructive-subtle`のボタン | 行ごとの破壊操作を見つけやすくしたい。頻度が高い、利用者の目的そのものである |
| 行の`Menu`の最後に区切り線を挟んで`destructive`の項目 | 頻度が低い、行の操作が多い、誤操作を避けたい |
| 一括選択して実行 | 多くの項目をまとめて整理する |

- 手間は被害の大きさに合わせる。元に戻せる操作は確認せず「元に戻す」を出し、単体の取り返せない操作は確認Dialog、広く影響するものは対象名の入力で確かめる。
- 言葉は結果に合わせる。他の場所に残るなら「外す」、完全に消えるなら「削除」。

## 避けるもの

生成されたUIに出やすく、内容を支えない表現。理由を説明できない限り使わない。

- すべての区画をカードで囲む、同じ形のカード(icon・見出し・文)を並べただけの構成
- 大きな数字と小さなlabelを並べただけの指標欄
- グラデーション、グラデーションの文字、色付きの太い左線、装飾目的のぼかし・ガラス
- 見出しの上の小さな英字label、`01`・`02`の番号飾り、見出しの一語だけの色付け、見出しを言い換えただけの説明文
- 絵文字や文字記号をiconの代わりにすること
- 中央揃えの多用、区画ごとに違う余白
- 必要のないmodal、hoverでしか見えない操作

## 確認

描画して確かめる。文書を読んだことや見本があることを確認の代わりにしない。

- 書き出した利用者ごとに、画面を開いてから目的を終えるまでを辿り、三つの問いに答える。
- 幅390px・768px・1280px以上で、明暗の両テーマを撮って見る。文字200%、長い文字列・0件・大量の件数でも崩れないか。
- keyboardだけで主操作まで届き、focusが見え、Dialogを閉じた後に元の場所へ戻るか。reduced motionで同じ結果に届くか。
- [避けるもの](#避けるもの)に当たるものがないか。
- 画面の言葉ごとに、伝えたいことと、レイアウトとデザインで試したこと、それで伝わらなかった理由を言えるか([伝える順](../DESIGN.md#内容と操作))。言えない言葉は消し、配置か見せ方で伝える。エラーの文と取り消せない操作の確認文は除く。
- 完了の画面から、次にどこへ行けるか。
