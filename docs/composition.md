# 画面の組み立て方

部品は見た目・状態・操作を保証する。画面の質は、何をどの順で見せ、どうまとめ、何を省くかで決まる。この文書は[判断基準](../DESIGN.md)を画面へ落とすときの手順と既定値を定める。部品の選び方は[部品の一覧](../components/README.md)に従う。

既定値から外れてよいのは、利用者・内容・操作の違いで理由を説明できるときだけにする。

## 利用者から始める

画面の判断はすべて、使う人の期待と目的に照らして行う。配置や見た目を決める前に、次を書き出す。

- **誰が使うか。** 一つの画面にも属性の違う利用者がいる(初めて使う人と毎日使う人、閲覧だけの人と管理する人、急いでいる人等)。想定する利用者を挙げ、優先する人を決める。
- **それぞれ何を期待して来るか。** この画面を開いたとき、何を見たいか、何を確かめたいか。
- **それぞれ何をしたいか。** この画面で終えたい作業と、そのために必要な情報・操作。
- **見た後に何をするか。** 画面を見た利用者の次の反応(操作する、判断する、別の画面へ進む、戻る)と、そのための手掛かりがどこにあるか。
- **どんな状況で使うか。** 端末・場所・頻度・急ぎ具合・他の作業の途中か。同じ人でも状況で求めるものが変わる。毎日使う人には密度と速さ、たまに使う人には迷わない手掛かりが要る。

書き出した内容は、分かっていることと仮定を分けて書く。根拠(利用者への聞き取り、利用データ、問い合わせ、試用の観察、依頼者から聞いた事実)があるものと、推測で補ったものを区別し、仮定に頼る判断は確かめる方法か、外れたときに直しやすい形を選ぶ。根拠のない利用者像で判断を固めない。

書き出したストーリーで、次の三つを問う。この文書の既定値は、これに答えるための手段である。

1. **叶えられるか。** 各利用者の期待と目的に、この画面で届くか。必要な情報と操作が揃っているか。
2. **阻害していないか。** 優先する人の目的を、他の人向けの情報・操作・装飾・確認が邪魔していないか。
3. **迷わないか。** 最初にどこを見て、次に何をすればよいかが分かるか。操作の結果を予測でき、結果を確かめられるか。

利用者ごとの目的が衝突し一つの画面で叶えられないときは、優先順位を決めるか、画面や表示の段階を分ける。

## 進め方

1. **利用者のストーリーを書く。** [利用者から始める](#利用者から始める)の問いに答え、優先する利用者の主な目的から、主操作を一つ決める。決まらなければ画面を分ける。
2. **内容を実際に近いデータで並べる。** 情報と操作を書き出し、利用者の目的に対する重要度と使う頻度で順位を付ける。よく使い重要なものほど目に入りやすい位置と強さにし、まれなものは奥(Menu・詳細画面等)へ下げる。最長の文字列・0件・大量の件数も用意する。仮の文言やタイル状の見本で配置を決めない。
3. **構造の案を複数出して比べる。** 方向の違う案を2〜3出し、領域と読む順を文字の図(ASCII)で示す。最初に思い付いた案はありがちな形になりやすい。各案を[三つの問い](#利用者から始める)で比べ、選んだ理由を残す。装飾を決める前に、配置と余白だけで関係が読めるかを見る。
4. **部品とtokenを選ぶ。** 既存の部品で組み、足りないものだけを新しく作る。token外の値が要るときは、先に共通契約へ足すかを判断する。
5. **状態を列挙する。** 初回読み込み・空・失敗・既存内容の更新失敗・権限なし・処理中のうち、その画面で起こるものを決めて作る。
6. **作った後に確かめる。** 下の[確認](#確認)を行い、利用者の目的に要らない要素を減らせないかを最後に検討する。

## 階層

- 強弱は、位置 → 余白 → 文字の大きさと太さ → 色の順で付ける。色・枠・背景は、前の手段で足りないときだけ足す。
- 主操作(`Button`の`primary`)は一つの領域に一つ。他は`secondary`・`outline`・`ghost`にする。破壊操作は主操作の隣に同じ強さで並べず、確認を挟む。
- 文字の段は次を既定にし、同じ画面で増やさない。

| 役割 | 指定 |
| --- | --- |
| ページの見出し | `font-heading text-heading` |
| 区画の見出し | `font-heading text-reading` |
| 本文 | `font-body text-body` |
| 補足・metadata | `text-caption text-reading-secondary` |
| 操作・label | `font-control text-action`(部品が指定済み) |

- 見出しの直下に、見出しを言い換えただけの説明を置かない。説明は、操作の前に知るべき情報があるときだけ書く。
- 読む順と見た目の順を一致させる。CSSで並び順を入れ替えない。

## 揃えと余白

- 左揃えを基本にする。中央揃えは空状態や単独の確認画面など、内容が一塊のときに限る。
- 揃える基準線を少なくする。label・入力・ボタンの左端を揃え、数字は右揃えにして`tabular-nums`を付ける。
- 画面の余白はtokenの段(`1`・`2`・`3`・`4`・`6`・`8`・`12`)から選ぶ。`p-5`・`gap-7`等の段外の値や、`[13px]`のような任意値を使わない。部品の内側の細かな調整は部品が持つ。
- 関係の近さを余白で示す。グループ内 < グループ間 < 区画間の順に広げる。

| 関係 | 既定 |
| --- | --- |
| labelと入力、見出しと補足 | `Field`等の部品に任せる(`gap-1.5`相当) |
| 同じグループの項目 | `gap-2`〜`gap-3` |
| グループ間 | `gap-6` |
| 区画間 | `gap-8`〜`gap-12` |
| 面の内側 | `p-panel` |

- 見出しの上の余白は下より広くし、見出しが後ろの内容に属して見えるようにする。

## まとめ方と面

- 区切りは、余白 → 区切り線(`border-t border-border`) → 面(`bg-card`と枠)の順に検討する。
- 面(カード)は、一つの対象をまとめ、それ自体を選ぶ・比べる・操作するときに使う。ページの区画をすべてカードにしない。カードを入れ子にしない。
- 影は浮く層(popup・Dialog)だけが持つ。ページ上の要素に影を付けず、枠と広い影を重ねない。
- 角丸は部品の`rounded-*`に従う。入れ子では内側を外側より小さくし、角を同心にする。

## 色

- 画面の面積の大半は`background`・`card`・`foreground`で占める。`primary`は主操作と選択に限る。
- `success`・`warning`・`destructive`・`info`は、その意味があるときだけ使う。区画の色分けや飾りに使わない。
- 色だけで状態を区別しない。icon・文言・形を併用する。
- 明暗どちらのテーマでも同じ構造で読めるようにする。テーマごとに配置を変えない。

## 文言

- ボタンとメニューは結果を表す動詞で書く(「保存」「削除する」「招待を送る」)。「OK」「はい」「送信」等の汎用語を避ける。
- エラーは、何が起きたかと、どうすればよいかを書く。利用者を責める表現や内部の用語を出さない。
- 同じものは同じ言葉で呼ぶ。画面ごとに言い換えない。
- 数字は半角、単位を付ける。日付・時刻・数値は利用者のlocaleで整形する。
- 日本語UIに英字の飾りlabel(見出し上の`OVERVIEW`等)を混ぜない。

## 状態と結果

- 初回読み込みは、最終的な形に近い骨組みを置き、内容が入ったときに配置が動かないようにする。
- 空状態は、なぜ空かと次の操作を示す。0件と取得失敗を同じ表示にしない。
- 既存の内容がある状態での更新失敗は、内容を残したまま`Banner`で伝える。
- 処理中は操作した場所で示す(`Button`の`pending`等)。画面全体を覆うloadingは、画面全体が使えないときだけにする。
- 結果の伝え方は[部品の一覧の対応表](../components/README.md#結果の伝え方)に従う。時間で消える表示を作らない。

## 表示条件

- 幅390pxから広い画面まで、横スクロールを出さない。表など横に長い内容は、その領域だけをscrollさせる。
- 長い文字列で崩さない。flexやgridの子に`min-w-0`を付け、一行に収める箇所は`truncate`と全文を読める手段を用意する。
- 操作領域は`h-control`(44px)を基本にする。`size="sm"`はpointer操作が主の密な画面に限る。
- 文字を200%に拡大しても、内容と操作に届くようにする。

## 避けるもの

生成されたUIに出やすく、内容を支えない表現。理由を説明できない限り使わない。

- すべての区画をカードで囲む、カードの入れ子、同じ形のカード(icon・見出し・文)を並べただけの構成
- 大きな数字と小さなlabelを並べただけの指標欄
- グラデーション、グラデーションの文字、色付きの太い左線、装飾目的のぼかし・ガラス
- 見出しの上の小さな英字label、`01`・`02`の番号飾り、見出しの一語だけの色付け
- 絵文字や文字記号をiconの代わりにすること。iconは一つの系統に揃える
- 中央揃えの多用、区画ごとに違う余白
- 必要のないmodal。背景の操作を止める理由がない作業はページやpanelで行う
- 時間で消える通知、hoverでしか見えない操作

## 確認

作った画面を実際に描画して確かめる。静止画で分かることと、操作して分かることを分ける。

- 書き出した利用者ごとに、画面を開いてから目的を終えるまでを辿る。叶えられるか、阻害していないか、迷わないか。最初に目に入るものと、次の操作の手掛かりが、そのストーリーに合っているか。
- 幅390px・768px・1280px以上で、明暗の両テーマを撮って見る。横スクロール・はみ出し・不自然な改行がないか。
- 操作中の状態が常に見えるか、誤操作を防ぎ取り消しや戻る手段があるか、前の画面の内容を覚えていなくても画面から判断できるか。
- 文字を200%にし、長い文字列・0件・大量の件数を入れて崩れないか。
- keyboardだけで主操作まで届くか。focusが見え、Dialogを閉じた後に元の場所へ戻るか。
- reduced motionで同じ結果に到達するか。
- この文書の[避けるもの](#避けるもの)に当たるものがないか。最後に、削っても利用者の目的を果たせる要素がないかを見る。
